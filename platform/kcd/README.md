The seats built so far, running on Harith's Core (`core/kcd_core`): they subclass `kcd_core.runtime.Seat`,
reach every tool through `ctx.tool` (checked by the PEP and audited), every memory layer through

## The golden path (`python -m kcd.demo`)

Marco R. (synthetic), 2026-10-12 21:40 in Italy:

1. **Red flag at home**: the Companion escalates; the Dispatcher pages the on-call uro-oncologist.
2. **Ibuprofen**: the Renal Guardian finds the last eGFR 123 days old and asks the Companion for a lab photo.
3. **Conflict**: with the fresh eGFR (52), NSAID x CKD G3a x hypertension x TKI → high; the Safety Verifier
   checks every citation against the Knowledge Model, the eGFR's plausibility and freshness.
4. **CT**: the Imaging Reader reads the key image (stub by default; Chrislin's model with `--ct-model-callable`,
   see `imaging/MODEL_CARD_chrislin.md`), calibrates, checks quality; verified.
5. **Genomics**: the Case Briefer asks for the hereditary context: VHL pathogenic → kidney-sparing options matter.
6. **Case pack**: SBAR with all four gates (sign-off, radiologist, nephrologist, geneticist); the clinician signs.
7. **Decision**: only the signed wording reaches the patient (Companion); the Archivist stores it.
8. **Memory**: two trial rules (avoid NSAIDs for Marco; route RCC red flags to the uro-oncologist) are confirmed
   by the clinician with signed releases and are active for the next episode. Then erasure.

## Memory: kcd_core layers → Cortex

Core's layers are the deck's (slide 24): 0-1 licensed knowledge (read-only for seats, served by the Knowledge
Model), 2 the hospital, 3 the patient. Cortex uses the same numbers:

| Layer | Cortex storage | Who writes |
|---|---|---|
| 3 patient | evidence (hash-chained, blobs), knowledge, idempotency keys, partition per patient | Imaging Reader, Genomics Interpreter, Archivist (rules) |
| 2 hospital | evidence (no patient identifiers) and knowledge | Archivist |

Proposing a rule needs the tool `cortex.knowledge_propose` as well as the layer (only the Archivist holds it).
Confirm / reject / re-verify / retire / erase are human-only Cortex calls; with `cortex.auth.release_verifier`
each needs the clinician's signed kcd_core `Release` for that exact rule (or `erase:<patient>`).

## Refusals (catalogue 2.0.0) and where they are enforced

| Seat | Refusal | Enforced by |

| | `report_to_patient` | only peer is the Safety Verifier; `patient.send` refused |
| | `alter_image` | `pacs.write` refused; PACS adapters have no write method; key image stored with its sha256 |
| Genomics Interpreter | `reclassify_variants` | lab class copied verbatim and verified before sending; `genomics.reclassify` refused |

| Archivist | `auto_confirm_rule` | `cortex.confirm_rule` refused; `CoreMemory` has no confirm; Cortex confirm needs a verified human |
| | `store_without_evidence` | Cortex: a rule must cite evidence in its own partition; unsigned decisions refused |
| | `write_general_weights` | `model.train_general` refused |
| Renal Guardian | `change_dose`, `prescribe`, `send_to_patient`, `alter_record` | actions refused; no write tools; content `dose_instruction`, `prescription` release-gated |
| Safety Verifier | `pass_failed_check` | a failed check declares `verifier.override` (refused, audited) and goes back to the sender as a rejection |

## Contract questions for Core

1. `ImagingSignal` can't carry "no result" (label and `p_calibrated` are required). An undecodable image or a
   failed model is written to evidence and audit (`imaging.no_signal`, decision `error`) and nothing is sent.
2. `ClinicianDecision` carries `decision_id` and `signature` but not the full `Release`, so only the Case Briefer
   can verify the clinician's Ed25519 signature; the Archivist trusts the routed, signed decision.
3. Reviewed manifest override: the Genomics Interpreter reads `fhir.get_conditions` (patient history).
4. Seats have no public `ctx.audit(...)`; the Imaging Reader takes the runtime's audit sink in its constructor.
